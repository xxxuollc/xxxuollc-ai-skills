# 简易接口文档 Skill

为前端开发者或前端大模型产出短小、可复制联调的接口说明。先从 Controller、DTO/VO、Service、Mapper、测试或真实响应核对契约；无法由代码确认的内容要标为待确认，不要补造字段、枚举值或成功提示。

## 参考标准

在当前仓库中，简易文档的写法和颗粒度参考：

- `.claude/docs/workspaces/余姚/余姚-数据接口/OUTPUT/YUYAO_NINGBO_API_USAGE.md`
- `.claude/docs/workspaces/余姚/余姚-数据接口/OUTPUT/YUYAO_NINGBO_MIGRATION_API.md`
- 工作区现有样例结构可参考 `.claude/docs/workspaces/余姚/余姚-数据接口/OUTPUT/YUYAO_NINGBO_SAMPLE_STRUCTURES.md`

将新文档放在对应功能工作区的 `OUTPUT/`；若已有统一 `API.md`，在其中增加该接口并链接到单独的前端简版文档，避免两份说明漂移。

## 建议结构

按接口复杂度裁剪，优先提供：

1. 标题：用业务名称说明接口用途。
2. 请求：HTTP 方法、路径、必填/可选参数表，以及一条可复制的 URL 或 curl。
3. 响应：标清统一响应外壳中承载业务数据的字段；给出最小有效 JSON 示例。
4. 字段表：列出前端需要消费的字段、类型、含义，以及空值/默认值。
5. 业务规则：仅写影响查询范围、排序、过滤、状态口径或副作用的规则。
6. 错误与接入提示：列出已由实现确认的常见错误和前端易误用点。

简单接口可以合并章节；没有分页、鉴权要求或特殊错误时，不必为了模板增加空章节。

## 撰写规则

- 以实现为准，不以历史接口名称、注释或旧文档推测当前行为。
- 区分 URL 查询参数、请求体、外层响应对象和 `data` 业务结构。
- JSON 示例只保留前端理解契约所需的最小结构；说明示例值是否为占位值。
- 字段表必须覆盖响应示例中的业务字段，并说明固定值、枚举来源和空值约定。
- 如兼容旧接口字段但业务数据源或语义已改变，明确写出兼容范围与差异。
- 如果响应字段无法表达完整状态，明确指出限制，禁止暗示前端可以可靠推导未提供的状态。
- 不记录密钥、个人信息、生产凭证或未确认的内部地址。
- 文档放入对应 `docs/workspaces/[功能]/OUTPUT/`，并更新 `CONTEXT.md`、必要时更新 `PROGRESS.md` 和 `API.md` 索引。

## 最小模板

````markdown
# [业务名称]接口

## 请求
- 方法：`GET|POST`
- 路径：`/[path]`
- 参数：`[name]`（必填/可选），[含义]

## 响应
外层响应的 `data` 为 [对象/数组]。

```json
{
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `field` | string | 含义及空值约定 |

## 业务规则
- [影响前端展示或查询的已确认规则]

## 错误
- [已确认的错误条件与提示]
````
